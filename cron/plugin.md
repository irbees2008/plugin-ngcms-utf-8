# Планировщик задач NGCMS

## Текущее устройство

Плагин больше не запускает отдельный планировщик и не читает собственный файл `crontab`. Он использует менеджер задач, уже встроенный в движок (`cronManager`), и не вносит изменений в ядро.

Единый список расписаний хранится в `engine/conf/cron.php`. Для просмотра и редактирования откройте в админ-панели **Система → CRON**. Внешний запуск задач настраивается отдельно; см. руководство [по настройке CRON](../../../docs/CRON_SETUP_GUIDE.md).

Страница настроек плагина содержит ссылку на системный раздел CRON. Плагин не должен быть местом для создания второго независимого расписания.

## Совместимость со старым API

`cron.php` сохраняет функции старого плагина, но передаёт их встроенному менеджеру:

- `cron_load()` возвращает задачи из `cronManager` в прежнем индексированном формате.
- `cron_save()` передаёт `$CRONDATA` встроенному менеджеру.
- `cron_register_task()` и `cron_unregister_task()` вызывают соответствующие методы менеджера.
- `cron_run()` делегирует запуск встроенному менеджеру.

Новый код должен напрямую использовать `cronManager`: `getConfig()`, `setConfig()`, `registerTask()` и `unregisterTask()`. Старые функции оставлены только для совместимости.

Файл `engine/conf/extras/cron/crontab`, если он остался от прежней версии, автоматически не импортируется и больше не исполняется. Перед обновлением перенесите необходимые задачи в **Система → CRON**, сверив идентификаторы плагинов, обработчики и расписание.

## Ограничения расписания

Формат и допустимые значения определяет `cronManager` движка. Совместимость плагина не добавляет поддержку диапазонов или шагов cron-выражения; расписание со списками и значением `*` обрабатывается самим менеджером. Поведение поля дня недели также определяется текущей реализацией движка.

## Обновление с предыдущей версии

После обновления проверьте задачи в **Система → CRON**. Старый обработчик `maintenance` и собственные файлы блокировки плагина удалены: запуск задач выполняет только встроенный менеджер.
