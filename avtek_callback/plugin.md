# AVTEK Callback

AVTEK Callback позволяет создавать несколько форм обратной связи, сохранять заявки в базе NGCMS и отправлять уведомления по Email, в Telegram и во внешнюю CRM. Формы можно вставлять в Twig-шаблоны, открывать в модальном окне или автоматически показывать в полной новости.

## Требования и установка

- NGCMS не ниже минимальной сборки, указанной в метаданных плагина, и PHP 8.x.
- Расширение PHP `mbstring` используется при обработке строк и обязательно для работы плагина.
- Расширение cURL необходимо для отправки в Telegram и CRM.
- Серверу требуется доступ к почтовой системе NGCMS и исходящим HTTPS-запросам, если используются внешние уведомления.

Установка:

1. Поместите каталог `avtek_callback` в `/engine/plugins/`.
2. Откройте **Утилиты → Плагины (extras)** в панели администратора.
3. Установите плагин, затем активируйте его, если движок показывает отдельное действие активации.
4. Откройте настройки плагина: `/engine/admin.php?mod=extra-config&plugin=avtek_callback`.
5. Создайте форму и вставьте её в шаблон сайта одним из способов ниже.

При установке создаются таблицы настроек, форм и заявок. Плагин не требует отдельной базы данных.

> **Внимание:** удаление плагина через деинсталлятор удаляет его таблицы, включая формы и сохранённые заявки. Перед деинсталляцией экспортируйте нужные данные и сделайте резервную копию.

## Первичная настройка

Рекомендуемый порядок:

1. Заполните общие настройки Email, Telegram и/или CRM на вкладке **Настройки**.
2. Создайте форму на вкладке **Формы**.
3. В форме выберите поля, отметьте обязательные, задайте подписи и при необходимости переопределите получателей и каналы для этой формы.
4. Сохраните форму и скопируйте готовый Twig-код из блока **Вставка формы на сайт**.
5. Отправьте тестовую заявку и проверьте её в разделе **Заявки**, а также в настроенном канале доставки.

Глобальные параметры используются как значения по умолчанию. Настройки, заполненные непосредственно в форме, имеют приоритет; пустые поля Telegram и CRM формы наследуют соответствующие глобальные значения. Получатели Email формы наследуют глобальный список, если поле Email в форме пустое.

## Глобальные настройки

### Email

**Email получателей по умолчанию** — адреса, на которые отправляются заявки, если в самой форме не указан отдельный список. Можно указать несколько адресов через запятую, точку с запятой или пробел.

**Адрес отправителя** — необязательный адрес `From`. Если оставить его пустым, плагин использует системную настройку отправителя NGCMS; конечный резервный адрес зависит от используемого почтового транспорта.

Плагин использует доступный почтовый механизм NGCMS/PHPMailer и не настраивает SMTP-сервер в этой форме. Если сайту требуется SMTP, сначала настройте почту в конфигурации NGCMS. Проверьте отправку обычной системной почты, прежде чем диагностировать плагин.

### Telegram

**Telegram Bot Token** — токен бота. Храните его как пароль и не публикуйте в шаблонах сайта, репозитории или открытых сообщениях.

**Telegram chat_id** — один или несколько ID получателей. Бот должен иметь право писать в соответствующий чат, группу или канал. Несколько ID можно разделить запятыми, точками с запятой или пробелами. Для конкретной формы можно указать собственные `chat_id`; если поле формы пустое, будет использован глобальный список.

Токен общий для всех форм; список чатов можно переопределить отдельно для каждой формы.

### CRM

Поле **CRM** принимает одно из значений:

- `webhook` — отправка JSON на ваш обработчик, интеграционный сервис или собственный endpoint;
- `bitrix24` — создание лида через входящий вебхук Bitrix24;
- пустое значение — CRM не используется, если не задано значение на уровне формы.

В поле **Настройки CRM (JSON)** вставьте корректный JSON без комментариев и завершающих запятых.

Для `webhook`:

```json
{
  "url": "https://example.com/integrations/lead",
  "header_auth": "Authorization: Bearer REPLACE_WITH_SECRET"
}
```

`header_auth` необязателен. Укажите его целиком как HTTP-заголовок; если авторизация не нужна, удалите это свойство. Endpoint получает POST-запрос с JSON-объектом заявки, в том числе с ID, названием формы, данными полей, метаданными, URL страницы и текстом заявки.

Для Bitrix24:

```json
{
  "webhook_url": "https://YOUR_DOMAIN.bitrix24.ru/rest/USER_ID/WEBHOOK_TOKEN/crm.lead.add.json"
}
```

Создайте входящий вебхук в Bitrix24 с разрешением на создание CRM-лидов и вставьте его адрес целиком. URL содержит секретный токен вебхука — храните его как пароль.

Bitrix24 получает имя, телефон и Email по подписям полей формы. Чтобы эти значения сопоставились без дополнительных преобразований, используйте подписи **Имя**, **Телефон** и **Email**. Другие поля включаются в текст комментария к лиду.

Тип CRM и JSON можно переопределить в настройках конкретной формы. Если поля формы пусты, применяются глобальные значения.

### Автовставка в полную новость

**ID формы** — ID существующей формы, которую нужно автоматически передавать в шаблон полной новости. По умолчанию используется форма с ID `1`.

**Режим**:

- **Встроенная форма** (`embed`) — поля отображаются прямо в новости;
- **Модальное окно** (`modal`) — в новости отображается кнопка, открывающая форму.

Фильтр плагина работает для полной новости. Чтобы увидеть форму, шаблон полной новости должен выводить переменную:

```twig
{{ plugin_avtek_cb|raw }}
```

Если переменная отсутствует в шаблоне, плагин не может показать автоматически вставленную форму, даже если настройки заполнены.

## Создание и настройка формы

На вкладке **Формы** нажмите **Новая форма**. Для уже созданной формы доступны редактирование, экспорт заявок этой формы и удаление.

### Основные параметры

- **Название** — обязательное имя формы, показывается в админке и используется в уведомлениях.
- **Slug** — необязательный технический идентификатор. Если оставить поле пустым, плагин сформирует его автоматически.
- **Email получателей** — список адресов только для этой формы. Если поле пустое, используется глобальный список Email.

### Стандартные поля

Для каждого поля можно включить отображение, отметить его обязательным, изменить подпись и placeholder.

| Поле | Тип в форме | Примечание |
|---|---|---|
| Имя | Текст | По умолчанию необязательное |
| Электронный адрес | Email | Для заполненного значения проверяется формат Email |
| Номер телефона +3 | Телефон | Placeholder по умолчанию — `+3`; его можно изменить. Это подсказка, а не проверка формата номера |
| Город | Текст | Свободный ввод |
| Варианты ответа | Выпадающий список | Варианты задаются по одному на строку |
| Календарь | Дата | Браузер передаёт дату в формате `YYYY-MM-DD` |
| Комментарий | Многострочный текст | Подходит для длинного сообщения |

Обязательность проверяется и в браузере, и на сервере. Поле Email дополнительно проходит серверную проверку формата.

### Дополнительные поля

Добавляйте по одному полю на строку в формате:

```text
Название|тип|required(0/1)|варианты
```

Примеры:

```text
Компания|text|1|
Тема обращения|select|0|Сервис,Продажи,Другое
Дата связи|date|0|
Email для ответа|email|0|
Комментарий|textarea|0|
```

Поддерживаются типы `text`, `email`, `phone`, `city`, `date`, `select` и `textarea`. Для `select` список вариантов задаётся через запятую. У остальных типов четвёртая часть строки обычно остаётся пустой. Символ `|` используется как разделитель, поэтому не включайте его в название поля или варианты.

Если для дополнительного поля указать неизвестный тип, браузер отобразит его как обычное текстовое поле. Для обязательного поля укажите `1`, для необязательного — `0`.

Подпись поля используется как название значения в Email, Telegram и таблице заявок. Это также важно для сопоставления стандартных полей Bitrix24.

### Поведение после отправки

- **Текст кнопки** — надпись кнопки отправки.
- **Сообщение после отправки** — текст успешного ответа.
- **После успешной отправки**:
  - **Показать сообщение в форме** (`inline`) — оставить посетителя на странице;
  - **Перейти по URL** (`redirect`) — перейти на указанный адрес после успешного ответа.
- **URL редиректа** — используйте вместе с режимом `redirect`.
- **Telegram chat_id** — необязательное переопределение списка чатов для этой формы; при пустом значении наследуется глобальный список.
- **Тема письма** — необязательная тема Email; если не задана, используется тема с названием формы.
- **Google Ads conversion JS** — JavaScript-код, который выполняется в браузере после успешной отправки. Добавляйте только проверенный код: он выполняется на странице сайта.
- **Шаблон встроенной формы** — необязательное имя PHP-файла из `engine/plugins/avtek_callback/tpl/`. Если поле пустое, используется стандартная разметка плагина. Для пользовательского шаблона можно взять за основу `skin_embed.php`.
- **CRM и настройки CRM** — переопределения глобальной CRM-конфигурации только для этой формы. Оставьте оба поля пустыми, чтобы использовать глобальные значения.

### Удаление формы

Удаление формы также удаляет связанные с ней заявки. Перед удалением выгрузите нужные заявки через XLS.

## Вставка формы на сайт

В редакторе формы скопируйте один из готовых примеров. Замените `1` на ID нужной формы.

### Встроенная форма в Twig

```twig
{{ callPlugin('avtek_callback.show', {'id': 1, 'mode': 'embed'})|raw }}
```

Плагин подключает стили и обработчик отправки через NGCMS. Для обычной серверной вставки дополнительные файлы JavaScript в шаблон добавлять не нужно.

### Форма в модальном окне

```twig
{{ callPlugin('avtek_callback.show', {'id': 1, 'mode': 'modal'})|raw }}
```

Плагин выведет кнопку открытия, затемнение и форму. Для модального режима предпочтительна прямая вставка через Twig; не загружайте этот HTML через `fetch` и `innerHTML`, поскольку браузер может не запустить встроенные скрипты модального окна.

### Автоматическая вставка в полную новость

Настройте ID и режим на вкладке **Настройки**, затем убедитесь, что в шаблоне полной новости есть:

```twig
{{ plugin_avtek_cb|raw }}
```

Вставка доступна только в полной новости. Для отдельной страницы, шапки или списка новостей используйте прямой Twig-вызов формы.

### Загрузка HTML формы через fetch

Плагин может вернуть HTML для встраивания по адресу:

```text
/plugin/avtek_callback/?sub=render&form_id=1&mode=embed
```

HTML, вставленный через `innerHTML`, не запускает вложенные скрипты. Подключите на основной странице CSS и обработчик отправки **один раз**:

```html
<link rel="stylesheet" href="/engine/plugins/avtek_callback/tpl/avtek_cb.css">
<script src="/engine/plugins/avtek_callback/tpl/avtek_cb_front.js?v=1" defer></script>
```

Затем загрузите HTML в нужный контейнер. Для `fetch` используйте режим `embed`; для модального окна используйте прямой Twig-вызов.

## Заявки и экспорт

На вкладке **Заявки** отображаются последние 200 записей: дата, форма, IP, страница, введённые данные, а также статусы Email и Telegram. Через кнопку **Скачать XLS** можно выгрузить все заявки; из списка форм доступен экспорт только по выбранной форме.

Заявка сохраняется в базе до отправки внешних уведомлений. Поэтому успешное сообщение посетителю означает, что заявка принята, но не гарантирует доставку Email, Telegram или CRM. После тестовой отправки проверьте соответствующие статусы в админке и сам канал доставки.

## Проверка и устранение проблем

### Проверить, что форма существует и отображается

Откройте, подставив ID формы:

```text
/plugin/avtek_callback/?sub=render&form_id=1&mode=embed
```

Если HTML не отображается, проверьте ID формы, активацию плагина и URL маршрута `/plugin/avtek_callback/`.

### Заявка сохраняется, но Email не приходит

Проверьте получателей формы и глобальный список, настройки отправки почты NGCMS, адрес отправителя и доступность почтового транспорта с сервера. Если список получателей пуст, отправка Email не выполняется.

### Не приходит сообщение в Telegram

Проверьте токен бота, `chat_id`, членство бота в группе/канале и его право отправлять сообщения. Если в форме задан список чатов, он имеет приоритет над глобальным.

### Не создаётся лид в CRM

Убедитесь, что в поле CRM указано `webhook` или `bitrix24`, JSON корректен, URL доступен серверу и настроена авторизация. Для Bitrix24 проверьте разрешение вебхука и подписи полей `Имя`, `Телефон`, `Email`. Вкладка заявок показывает статусы Email и Telegram; CRM-ответ не отображается в этой таблице.

### Форма через fetch не отправляется или выглядит без стилей

Подключите `avtek_cb.css` и `avtek_cb_front.js` на странице-контейнере, как описано в разделе [Загрузка HTML формы через fetch](#загрузка-html-формы-через-fetch). Не подключайте обработчик повторно, если он уже добавлен шаблоном.

## Безопасность и хранение данных

- Используйте HTTPS для сайта, CRM webhook и интеграционных endpoint.
- Не публикуйте Telegram-токен, Bitrix24 webhook URL и секреты в открытом коде.
- Ограничьте доступ к админке: в базе хранятся введённые посетителями данные, IP-адрес, User-Agent и адрес страницы.
- Ограничьте срок хранения заявок и включите резервное копирование базы с учётом требований вашего сайта.
- Экспортируйте заявки и сделайте резервную копию до удаления формы или деинсталляции плагина: соответствующие действия удаляют данные.
