# Lazy Load изображений

Плагин добавляет нативные атрибуты отложенной загрузки HTML-изображениям на публичных страницах сайта. JavaScript-библиотеки и изменения шаблонов не требуются.

## Установка и включение

1. В панели управления откройте раздел плагинов, установите и активируйте **Lazy Load изображений**.
2. Откройте настройки плагина. При первом открытии используются значения по умолчанию: `enabled = 1`, `skip_first = 2`.
3. При необходимости укажите CSS-классы, ID и части URL, изображения с которыми нужно исключить.
4. Очистите кеш страницы, если он включён, и проверьте исходный HTML публичной страницы.

Для ручной установки скопируйте каталог `engine/plugins/lazy_load/` целиком. Отдельный `version.ini` не используется: метаданные плагина находятся в этом файле `plugin.md`.

## Настройки

| Параметр | Назначение |
|---|---|
| `enabled` | `1` — включить обработку, `0` — отключить. По умолчанию `1`. |
| `skip_first` | Число первых изображений страницы, которые не изменяются. По умолчанию `2`; значение ограничивается диапазоном 0–20. |
| `exclude_classes` | Список через запятую. Совпадение проверяется по отдельному классу или точному ID самого `<img>`, например `no-lazy, logo, hero-image, #site-logo`. |
| `exclude_urls` | Список через запятую. Изображение пропускается, если `src` содержит одну из строк, например `/logo/, avatar, banner-top`. |

## Результат и исключения

Для подходящего изображения после первых N плагин добавляет только отсутствующие атрибуты:

```html
<img src="/uploads/photo.webp" loading="lazy" decoding="async" alt="Фото">
```

Первые N изображений страницы остаются без изменений. Это приблизительная настройка первого экрана: плагин не определяет фактическое расположение изображения в viewport.

Не изменяются изображения без `src`, с `data:` в `src`, с атрибутами-маркерами `data-lazy*`/`data-no-lazy*`, с исключёнными классами, ID или URL. Явные `loading="eager"` и `fetchpriority="high"` также сохраняются. Обрабатываются только запросы `GET` и `HEAD`; административные и AJAX-запросы пропускаются.

Плагин обрабатывает HTML через output buffering и регулярное выражение для тегов `<img>`, не пересобирая остальную разметку. В ядре NGCMS хук `index` выполняется до вывода главного шаблона.
Не включайте одновременно другой плагин, который меняет атрибуты загрузки этих же изображений.

## Проверка

Откройте исходный HTML публичной страницы. У изображения, которое не попадает под исключения и не входит в первые N, должны появиться `loading="lazy"` и `decoding="async"`. Если атрибут уже задан шаблоном, его значение сохраняется.
