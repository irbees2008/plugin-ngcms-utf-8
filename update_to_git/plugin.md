# Обновление CMS из GitHub

Плагин отдельно обновляет ядро из `irbees2008/ngcms-core` и плагины из `irbees2008/ngcms-plugins`. Настройки источников находятся в `params.php`; корень репозитория плагинов сопоставляется с каталогом `engine/plugins/`.

## Перед использованием

- Создайте резервные копии файлов сайта и базы данных.
- Для ядра `base_ref` берётся из `engineVersionBuild` — commit установленной сборки, который должен существовать в GitHub.
- При первой проверке плагинов плагин только сохраняет текущий commit ветки `master` как начальную точку и не меняет файлы. Последующие проверки применяют изменения, появившиеся после этой точки. Локальные отличия от начального снимка автоматически не синхронизируются.
- Проверьте список `except`: файлы из него не обновляются и не удаляются.
- Запускайте обновление только для доверенного репозитория. Операция не выполняет миграции базы данных.

## Работа плагина

1. Администратор отдельно проверяет ядро или плагины.
2. Плагин показывает список файловых изменений, не изменяя файлы сайта.
3. После просмотра списка администратор нажимает «Применить обновления». Файлы скачиваются и применяются последовательно. Удалённые файлы удаляются, переименованные — загружаются под новым именем, после чего удаляется прежнее имя.
4. Для плагинов commit-указатель сохраняется только после успешной обработки всех файлов; при ошибках проверка изменений повторится.

RPC-запросы проверяют токен и права администратора. URL загрузки должен вести на HTTPS-файл настроенного репозитория. Путь назначения проверяется на выход за каталог сайта и символические ссылки; новые файлы сначала загружаются во временный файл.

Обновление файлов не является транзакцией: если отдельный файл не удалось применить, остальные файлы могут обновиться. В таком случае проверьте список результата и восстановите сайт из резервной копии либо повторите обновление после устранения ошибки.
